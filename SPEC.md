# Граф денег — спецификация

Трек «Финансы», задача Freedom: восстановление финансовой структуры организованной группы по транзакционной сети.

## Карточка идеи

- **Проблема:** AML-аналитик банка знает только нижний уровень — 81 клиента (3,6% сети) — и вручную прослеживает переводы на 4 колена: часы на узел, недели на сеть. 96% сети — 2 167 из 2 248 узлов — остаются невидимыми, приоритет проверки выбирается интуитивно, блокируется только нижний уровень.
- **Цитата из ТЗ:** «Кто стоит выше — кто собирает эти деньги, через кого их прогоняют и кто в итоге ими распоряжается — приходится восстанавливать вручную.»
- **Как сейчас:** ручная трассировка по выпискам и интуитивный выбор, кого смотреть первым.
- **Решение:** локальный пайплайн за секунды превращает выгрузку переводов в граф с объяснимыми ролями, кластерами и приоритетом. Карта сети с поиском по gid. AI-ассистент отвечает на вопросы аналитика по графу и подсказывает, какие данные запросить дальше.
- **Ядро:** ранжированный список «кого проверять первым» с объяснимой ролью каждого узла — чтобы аналитик за минуты переходил от 81 курьера к точкам консолидации и координаторам.
- **Не ядро, бэклог:** устойчивость сети при изъятии узлов, ML-аномалии, зеркало в Supabase, украшения интерфейса.
- **Почему агент:** код считает метрики, роли, кластеры и приоритет по порогам. Ассистент ходит по графу инструментами — узел, соседи, путь к seed, кластер, топ; собирает карточку узла, оценивает полноту данных и формулирует следующий запрос. Пересчитывает приоритет, когда аналитик исключает узел или добавляет seed. Останавливается перед «сформировать запрос в правоохранительные органы».
- **Сцена 3:** аналитик помечает узел как легальный бизнес или добавляет нового seed → пересчёт → в топе меняется лидер.
- **Сцена 4:** «сформировать запрос» — только после подтверждения человеком.
- **Успех:** одна команда, ~3 секунды на всю сеть при лимите 5 минут; 2 248 узлов с ролью и обоснованием в цифрах; топ-30 — 1,3% сети, в них сходятся деньги 15 из 50 активных курьеров; жюри называет gid → узел на карте со связями за секунды.
- **Отличие:** в отличие от ручной трассировки и скоринга «чёрным ящиком» — объяснимые правила с цифрами у каждого узла и ассистент, который отвечает по графу со ссылками на узлы.
- **Масштаб и пилот:** до ~1 млн узлов — igraph или DuckDB, один обход от seed вместо поиска предков для каждого узла, приближённый betweenness, Leiden вместо Louvain. Тот же подход — для других типологий и банков. Пилот с Freedom; привязка к перечню признаков подозрительных операций АФМ.
- **Риск:** разметки ролей нет — роли могут оспорить. Закрываем: пороги в одном месте, у каждого узла цифры в `evidence`, формулировки — гипотезы для проверки.
- **One-liner:** «За 3 секунды поднимаем сеть от 81 курьера до точек консолидации и объясняем, кого проверять первым — и пересчитываем, когда аналитик уточняет данные.»

## Must-have из ТЗ → как закрываем

| # | Требование | Как |
|---|---|---|
| 1 | Воспроизводимый пайплайн | `python pipeline.py --data data --out out` — около 3 секунд |
| 2 | Роль и скор у каждого узла | 2 248 строк: `role`, `role_score`, `evidence` с цифрами |
| 3 | Критерии задокументированы и объяснимы | README → «Критерии ролей и пороги»; карточка узла показывает сработавшее правило |
| 4 | Кластеризация | Louvain, 71 кластер, гипотеза по составу ролей |
| 5 | Топ-лист + визуализация | `top_nodes.csv` — 30 строк; карта: роли цветом, стрелки, поиск по gid |

## Бонусы, которые берём

- обрыв 4-го колена отделён от конечных получателей;
- временные паттерны: транзит за ≤ 2 дня, синхронные переводы за один день;
- возвратные потоки;
- AI-ассистент аналитика;
- карточка узла;
- оценка полноты: какие данные запросить дальше.

## Определение готовности

- одна команда с чистого клона создаёт три CSV меньше чем за 5 минут;
- любой из команды объясняет роль любого gid за минуту;
- 4 сцены демо проходят локально;
- README — по разделам ТЗ.
