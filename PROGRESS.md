# Интеграция и контрольный запуск

Базовая версия: `1e56e56`, получена из `origin/main` обычным pull без rebase. В ней опубликованы Compose, PostgreSQL, шесть таблиц, загрузчик данных, `serve.py`, ассистент и веб-интерфейс.

При начале проверки Docker Engine 29.8.0 отвечал на `docker info`, Compose v5.5.1 был доступен. `.env` подготовлен из `.env.example`, ключ OpenAI пуст. Выполнена команда `docker compose up --build -d`; образ PostgreSQL скачан.

**Контрольный запуск заблокирован состоянием машины.** Сборка приложения упала при установке pandas: `OSError: [Errno 30] Read-only file system`. Отдельная попытка записи в Docker также получила `containerd ... meta.db: read-only file system`. На диске C: оставалось около 7 МБ. Удалены только созданные интегратором временные Vercel CLI и отдельное проверочное Python-окружение, исходники и результаты сохранены. Позднее свободное место увеличилось до 3,9 ГБ, но Docker Desktop и docker.exe по прежнему пути уже отсутствовали; ожидается уточнение о переустановке.

Контейнеры приложения и базы **не запущены**, ответ `/api/health` не получен. Этот результат не считается проверкой работоспособности Compose.

Повторная попытка после восстановления Docker: Engine 29.8.0 снова отвечает. При старте было около 1,1 ГБ свободного места. Все зависимости, включая pandas 3.0.1 и OpenAI SDK 3.19.0, установились внутри сборочного слоя, однако сохранение слоя завершилось ошибкой `buildkit/containerd-overlayfs/metadata_v2.db: read-only file system`. Свободное место уменьшилось до 11 МБ. Дополнительно удалена только созданная интегратором временная папка Python-пакетов `work/packages`, освобождено около 230 МБ. Для следующей попытки требуется освободить не менее 5 ГБ и перезапустить Docker Desktop; успешный запуск по-прежнему не подтверждён.

README переведён на фактическую локальную архитектуру и ссылается на DOCKER.md. Уточнены требования к месту и сохранению тома. Порт приложения ограничен `127.0.0.1`; добавлена проверка готовности приложения; `/api/health` возвращает HTTP 503 при недоступности настроенной БД; ошибка загрузчика прекращает запуск. Версия OpenAI SDK закреплена на 3.19.0 (скачана во время сборки; live-вызов не проверен). Математические формулы, пороги и веса не менялись; `web/` не редактировался.

Следующие проверки: `/api/health`, браузерный сценарий, записи ассистента и подтверждений в PostgreSQL, повторная загрузка без дубликатов, сохранность данных после `down` и повторного запуска, пайплайн и `check.py` внутри контейнера. Успешный replay не считается проверкой live-модели.

Риски по чтению кода, ещё до полного прогона: ошибки записи журнала ассистента подавляются; повторное подтверждение не защищено от дублирования.
